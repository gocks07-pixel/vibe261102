# EXE 빌드 계획 (승인 대기)

2026-11-05 작성. 사용자가 "EXE 빌드 진행해 줘"라고 하면 구현한다. 2.0 다음, 마지막 단계.
게임 내용(퀘스트 · 아이템 · 몬스터)과 아이템 id · 세이브 형식은 바꾸지 않는다 (기존 세이브 유지).

---

## 1. EXE 두 가지
| | 테스트용 (개발자 버전) | 플레이어용 |
|---|---|---|
| 빌드 명령 | `npm run build:dev` | `npm run build:player` |
| 파일 이름 | `RPG Adventure DEV 2.0.0.exe` | `RPG Adventure 2.0.0.exe` |
| 테스트 모드 (`src/dev.js`) | 포함 | **제외** (파일 자체를 넣지 않음) |
| 창 제목 | RPG 대모험_HC (DEV) | RPG 대모험_HC |
| 세이브 폴더 | `문서/Hannyomi_DEV` | `문서/Hannyomi` |

- 원본은 하나. 빌드 명령만 두 개 (electron-builder 설정 2개)
- 게임은 테스트 코드가 없으면 테스트 모드 버튼을 보여 주지 않음 → `dev.js`를 빼도 오류 없음 (index.html의 dev.js 줄은 없어도 동작하도록 정리)
- **세이브 폴더를 나누는 이유**: 테스트 모드는 시작할 때 슬롯 C를 덮어쓴다. 같은 PC에서 테스트해도 실제 세이브가 지워지지 않게

## 2. 세이브 유지 (재배포해도 안 지워짐)
- 세이브는 EXE 바깥 `문서/Hannyomi/save_A·B·C.json`에 저장 (지금도 그렇다). EXE를 새 버전으로 바꿔도 그대로
- 저장은 임시 파일에 쓴 뒤 바꿔치기 + `save_X.backup.json` 백업 (지금도 그렇다)
- 설정(배경음 · 효과음 · 키)은 Windows 앱 데이터 폴더 → EXE 이름 "RPG Adventure"를 바꾸지 않으면 유지
- 앞으로 버그 수정 원칙: 내부 id는 바꾸지 않는다. 세이브 형식이 바뀌면 불러올 때 변환하는 코드(`G.Save.migrate`)를 넣는다

## 3. 버전 표시
- 타이틀 화면 오른쪽 아래에 작게 `v2.0.0` (package.json 버전을 그대로 읽음)
- 테스트용은 `v2.0.0 DEV`
- 버그 수정 때마다 버전을 올린다 (2.0.1, 2.0.2 …)

## 4. 오류 자동 기록
- 게임에서 오류가 나면 `문서/Hannyomi/오류기록.txt`에 자동으로 쌓는다
  - 날짜 · 시간, 버전, 맵, 캐릭터 레벨 · 직업, 오류 내용과 위치(파일 · 줄)
- 같은 오류가 반복되면 횟수만 늘림 (파일이 너무 커지지 않게, 최근 200줄까지)
- 오류가 나도 게임은 가능한 한 계속 진행

## 5. 🐞 버그 신고 버튼
- 위치: 메뉴(Esc) 안 "🐞 버그 신고" + 단축키 **F9** (게임이 멈춘 듯할 때도 열 수 있게)
- 순서
  1. 신고 창: "무슨 일이 있었나요?" 입력 칸 (안 적어도 됨) → [신고 파일 만들기] / [취소]
  2. 자동으로 폴더 생성: `문서/Hannyomi/버그신고/날짜_시간/`
     - `신고내용.txt` — 플레이어가 적은 글
     - `게임정보.txt` — 버전, 캐릭터 이름 · 레벨 · 직업, 현재 맵, 진행 중인 퀘스트, 플레이 시간
     - `오류기록.txt` — 최근 오류
     - `화면.png` — 신고 직전 게임 화면
     - `save_X.json` — 지금 플레이 중인 세이브 복사본
  3. 폴더가 자동으로 열리고 안내: "신고 파일을 만들었어요! 열린 폴더 안의 파일들을 보내 주세요. 게임은 계속하셔도 돼요."
- 인터넷으로 자동 전송하지 않는다 (서버 불필요, 아이 PC에서 데이터를 밖으로 보내지 않음)
- PC 사용자 이름 등 개인정보는 넣지 않는다
- 테스트용 · 플레이어용 모두 포함
- 브라우저(아티팩트) 판에서는 폴더 대신 `게임정보 + 오류기록` 내용을 화면에 보여 주고 복사 버튼 제공

## 6. 버그 수정 흐름 (문서로 정리해 사용자에게 전달)
1. 플레이어가 버그 신고 폴더의 파일을 카톡 · 메일로 보냄
2. 사용자가 새 Claude 세션(저장소 `gocks07-pixel/vibe261102`, 브랜치 `hannyomi-backup`)에 파일을 올리고 "버그 고쳐 줘"
3. Claude: 오류기록으로 위치 찾기 → 세이브로 재현 → 수정 → 회귀 테스트 → 버전 올리기 → GitHub 백업
4. 사용자가 Windows PC에서 새 EXE 빌드 → 플레이어에게 전달 → 플레이어는 EXE만 교체 (세이브 유지)

## 7. 빌드 안내서 (`docs/EXE_빌드_안내.md`)
- 처음 한 번: Node.js 설치, GitHub에서 받기, `npm install`
- 매번: 최신 받기 → `npm run build:player` (또는 `build:dev`) → `dist` 폴더의 EXE
- 그림 없이 따라 할 수 있게 명령 한 줄씩
- 이 클라우드 환경에서는 Windows EXE를 직접 만들 수 없으므로(Windows 도구 필요) 사용자 PC에서 빌드

## 8. 함께 정할 것 (사용자 확인 필요)
- 엔딩 크레딧 문구 → "과금없이 즐기는 연희의 RPG 대모험 / 기획 · 개발 : HC / 플레이해 주셔서 감사합니다!" (가능 확인만 함, 적용 여부 확인)
- 타이틀 화면에서 "아르셀리아 연대기" 줄 삭제 (가능 확인만 함, 적용 여부 확인)

## 9. 확인 방법
- 플레이어용 빌드에 `dev.js`가 없고 테스트 모드 버튼이 안 보이는지
- 테스트용은 `Hannyomi_DEV` 폴더에 저장되는지
- 버전 표시, 오류 기록(일부러 오류를 내 봄), 버그 신고 폴더 생성 · 화면 캡처 · 세이브 복사
- 회귀 테스트 전체 + 2.0 테스트
- 문서 · README · ROADMAP 갱신, GitHub 백업
