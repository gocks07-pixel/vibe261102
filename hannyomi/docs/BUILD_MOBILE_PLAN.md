# 모바일 1차 계획서 (아이폰 · 갤럭시)

2026-11-05 작성. 사용자가 "진행해 줘"라고 하면 구현한다. 브랜치 `hannyomi-mobile` 에만 커밋·푸시 (`hannyomi-backup` 은 EXE 작업 중이라 건드리지 않음).

## 정해진 것
- 방식: 웹(PWA)으로 배포 → 아이폰은 사파리 "홈 화면에 추가", 갤럭시는 크롬. 나중에 원하면 갤럭시 APK
- 버전 숫자는 그대로(2.1.0). 화면에 "모바일" 표시만 붙인다. 두 브랜치를 합칠 때 2.2.0
- 1차 = M1 화면 맞추기 · M2 터치 조작 · M4 세이브 지키기 (플레이 가능 + 세이브 안전)
- 2차 = M3 창 터치 개선 · M5 앱처럼 설치 · M6 성능 · M7 배포
- 앱 아이콘: 1차가 끝나면 시안 몇 개를 만들어 사용자가 고른다 (그때까지 임시 아이콘)

## 지키는 것
- 내부 id · 세이브 형식(`G.Save.VERSION` 4) · `hny_*` 키는 바꾸지 않는다
- 게임 규칙 코드는 건드리지 않는다. 터치 버튼은 "키를 누른 것"으로 바꿔 `G.Input` 에 넣는다 → 키 설정(`G.Keys.map`)도 그대로 따른다
- 터치 기능은 터치 화면에서만 켜진다. PC 브라우저 · EXE 는 지금과 똑같이 동작
- 테스트 모드(`src/dev.js`)는 그대로 둔다 (브라우저판은 원래 불러오지 않음)
- 그림 파일 없이 코드로 그린다 (버튼 문양도 CSS · SVG)

## M1. 화면 맞추기
지금은 1280×720 화면을 `G.Game.resize()` 로 비율을 유지해 줄인다. 아이폰 가로(약 844×390)에서는 0.54배, 좌우에 검은 띠가 약 75px씩 생긴다.

1. `index.html` viewport: 확대 금지, 노치 영역까지 쓰기 (`viewport-fit=cover`), 홈 화면 실행 시 전체 화면용 meta
2. 확대 · 스크롤 · 당겨서 새로고침 · 길게 눌러 글자 선택/돋보기 막기 (`touch-action`, `overscroll-behavior`)
3. `resize()` 가 `visualViewport` 크기와 노치 · 홈 바 여백(safe-area)을 빼고 계산. 주소창이 나왔다 들어갈 때도 다시 맞춘다
4. 세로로 들면 "가로로 돌려 주세요 📱↻" 화면 (게임은 잠시 멈춤)
5. 메뉴에 "전체 화면" 버튼 (갤럭시 크롬. 아이폰은 홈 화면에 추가하면 자동 전체 화면이라 안내 문구로)
6. 소리: 지금은 키보드 · 마우스를 눌러야 소리가 켜진다 (`src/core/audio.js` unlock) → 첫 터치(`pointerdown` · `touchend`)에도 켜지게. 아이폰 무음 스위치를 켜면 소리가 안 날 수 있다는 안내 한 줄 (처음 한 번)
7. 시작 화면 오른쪽 아래 버전 표시: `v2.1.0 모바일`. 버그 신고 · 오류 기록에도 "모바일"과 기기 정보(아이폰/갤럭시, 화면 크기)

## M2. 터치 조작 버튼
게임 화면(#game)은 줄어들지만 버튼은 줄어들지 않게 화면 맨 위에 따로 얹는다 (손가락 크기 그대로 약 56~64px). 반투명, 여러 손가락 동시에 (이동하면서 점프 · 공격).

```
┌──────────────────────────────────────────────────────────────┐
│ [맵 이름]                     [스탯][장비][인벤][스킬][퀘][지도][≡]│
│                                                    [퀘스트 안내]│
│                                                              │
│                                                              │
│                                          [1] [2] [3]          │
│     [↑]                                  [4] [5] [6]  [HP][MP]│
│ [←]     [→]                         [대쉬]                     │
│     [↓]                                    [공격]   [점프]      │
└──────────────────────────────────────────────────────────────┘
```

1. 왼쪽 방향 패드: 누른 채 손가락을 미끄러뜨리면 방향이 바뀐다. ↑ = 포탈 · NPC 대화, ↓ 누른 채 점프 = 발판 아래로. 좌우 동시 처리는 지금처럼 `lastH`
2. 오른쪽 행동 버튼: 공격(누르고 있으면 연속), 점프(공중에서 한 번 더 = 2단 점프, ↑+점프 그대로), 대쉬
3. 스킬 1~6: 하단 상태창의 스킬 칸과 같은 아이콘 · 재사용 대기 · MP 부족 표시. 빈 칸은 흐리게
4. HP · MP 물약 버튼: 남은 개수, 자동 물약 켜짐 표시 (지금 HUD 와 같은 규칙)
5. 위쪽 창 버튼: 스탯 · 장비 · 인벤토리 · 스킬 · 퀘스트 · 지도 · ≡ 메뉴(Esc 와 같음: 열린 창이 있으면 닫고, 없으면 메뉴). 🐞 버그 신고는 메뉴 안에 이미 있음
6. 대화: 대화창이 열려 있으면 게임 화면을 누르면 다음으로 (Enter 와 같음). 선택지 버튼은 지금처럼 직접 누름
7. NPC · 포탈 누르기: 지금 `mousedown` → 탭도 똑같이 동작하는지 확인 (필요하면 `pointerdown` 으로)
8. 장비 · 인벤토리 "더블클릭"(입기 · 사용): 휴대폰은 더블클릭이 잘 안 잡혀서 "같은 칸을 빠르게 두 번 탭"을 더블클릭으로 처리. 오른쪽 위 퀘스트 두 번 탭 = 길 안내도 같이 해결 (원래 2차 M3 항목이지만 이게 없으면 장비를 못 입어서 1차에 넣음)
9. 메뉴 → "터치 버튼 설정" 창: 크기(작게/보통/크게), 투명도, 좌우 바꾸기(왼손잡이), 터치 버튼 켜기/끄기(자동 · 항상 · 끔). 저장은 새 키 `hny_touch` (세이브와 별도, 기존 설정 `hny_settings` 형식도 그대로)
10. 컷신 · 엔딩 · 캐릭터 만들기 · 타이틀에서는 버튼 숨김. 캐릭터 이름 입력은 휴대폰 자판이 뜨는지 확인
11. 휴대폰에서 F1 조작법 창 → "버튼 안내" 그림으로, 키 설정 메뉴는 숨김 (PC 는 그대로)

새 파일: `src/core/touch.js` (버튼 → 키 입력), `src/ui/mobile.js` (버튼 그리기 · 설정 창 · 세로 안내), `css/mobile.css`

## M4. 세이브 지키기
아이폰 사파리는 오래 안 쓰면 저장 데이터를 지울 수 있고, 창을 닫을 때 `beforeunload` 가 오지 않아 마지막 진행이 저장되지 않을 수 있다.

1. 앱을 내리거나 다른 앱으로 갈 때 저장: `pagehide` · `visibilitychange`(숨김) 에서 `G.Game.save(true)` (PC 에도 해가 없음)
2. 저장 공간 지키기 요청: `navigator.storage.persist()` (갤럭시 크롬은 대부분 허락, 아이폰은 홈 화면에 추가했을 때 효과)
3. **세이브 내보내기** (메뉴 + 타이틀의 슬롯 고르기 화면)
   - 파일로 저장: `save_A.json` — EXE 의 `문서\RPG Adventure\Save Data\save_A.json` 과 같은 내용 (`{v, slot, time, d}`)
   - 복사하기: 같은 내용을 글자로 복사 → 카카오톡 "나에게 보내기"에 붙여 넣어 보관
4. **세이브 가져오기**
   - 파일 고르기 또는 글자 붙여 넣기 → 어느 슬롯에 넣을지 선택 → "Lv.37 ○○ (전사) 를 슬롯 B 에 넣을까요?" 확인
   - 덮어쓸 슬롯에 세이브가 있으면 먼저 자동 백업 (`_backup`, 지금 있는 방식)
   - 옛 버전 세이브도 불러올 때 `G.Save.upgrade()` 가 그대로 변환. 형식이 이상하면 "세이브 글자가 잘렸어요" 안내하고 아무것도 바꾸지 않음
   - EXE 세이브 ↔ 휴대폰 세이브를 서로 옮길 수 있다
5. 사파리에서 홈 화면에 추가하지 않고 하고 있으면 처음 한 번 "홈 화면에 추가하면 세이브가 더 안전해요 (공유 → 홈 화면에 추가)" 안내 + "가끔 세이브 내보내기를 해 두세요"

## 고치는 기존 파일 (작은 수정만)
- `index.html`: viewport · meta, `css/mobile.css` · `touch.js` · `mobile.js` 불러오기
- `src/main.js`: `resize()` (safe-area · visualViewport), `pagehide` 저장, 대화 중 화면 탭
- `src/core/audio.js`: 터치로 소리 켜기
- `src/ui/ui.js`: 두 번 탭 = 더블클릭, 창 끌기를 손가락으로도 (`mousedown` → pointer)
- `src/ui/windows2.js`: 메뉴에 "터치 버튼 설정 · 세이브 내보내기/가져오기 · 전체 화면" (휴대폰에서만 보이는 버튼은 휴대폰에서만)
- `src/ui/windows.js`: 버전 표시 "모바일", 슬롯 화면에 내보내기/가져오기
- `src/core/save.js`: 내보내기 · 가져오기 함수 (읽기 · 쓰기 방식은 그대로, 형식 변경 없음)
- `src/ui/bugreport.js` · `src/core/errlog.js`: "모바일" · 기기 정보 한 줄

## ① 아이폰 "크게 보는 방법" 안내
- **처음 한 번**: 아이폰 사파리로 처음 열어 타이틀이 뜰 때. 1차의 "휴대폰으로 플레이하기" 안내와 합쳐서 창은 한 번만 뜬다
  - 방법 1 (추천) **홈 화면에 추가**: 사파리 아래 공유 버튼 □↑ → "홈 화면에 추가" → 홈 화면의 별 아이콘으로 열기 → 주소창 없이 크게, 세이브도 더 안전
  - 방법 2 **잠깐만 크게**: 주소창 왼쪽 "가가" → "툴바 막대 가리기" (사파리를 다시 열면 원래대로)
  - 공유 버튼 · 가가 버튼 모양은 코드로 그린 작은 그림 (이미지 파일 없음)
  - 한 줄 주의: "사파리에서 하던 세이브는 홈 화면 앱에서 안 보여요 → 💾 세이브 옮기기 → 글자 복사 → 홈 화면 앱에서 글자 붙여넣기"
- **다시 보기**: 타이틀 화면에 "📱 크게 보는 방법" 버튼 (아이폰 · 아이패드 사파리에서만. 홈 화면 앱으로 열었으면 이미 크게 보는 중이라 숨김)
- 본 적이 있는지는 `hny_touch` 에 기억 (세이브와 별도)

## ③ 게임 창을 휴대폰에 맞게 키우기
지금: 게임 화면(1280×720)이 휴대폰에서 약 0.5배로 줄어 창 글자 13px → 실제로는 약 6~7px. 너무 작다.

1. **창 확대**: 터치 모드에서 창(`.win`)을 휴대폰 화면에 맞는 배율로 키운다 (목표: 실제 글자 크기가 PC 의 약 85%)
   - 배율 = 0.85 ÷ 게임 화면 배율 (아이폰 · 갤럭시 약 1.6~1.8배, 아이패드는 거의 그대로), 최대 1.9배
   - 창이 화면 밖으로 나가지 않게 크기와 위치를 자동으로 맞춤
2. **창 자동 정렬**: 창이 여러 개 열리면 옆으로 나란히 (예: 상점 + 인벤토리, 창고 + 인벤토리, 장비 + 인벤토리). 둘이 함께 안 들어가면 배율을 조금 줄인다. 창을 열고 닫을 때마다 다시 정렬 (손가락으로 끌어 옮기는 것도 그대로 됨)
   ```
   [휴대폰 · 상점에서 팔 때]
   ┌──────────────────────────────────────────┐
   │ ┌── 상점 ──────────┐ ┌── 인벤토리 ─────┐ │
   │ │ 물약   200G [사기]│ │ ▢▢▢▢▢▢▢▢       │ │
   │ │ 해독약 300G [사기]│ │ ▢▢▢▢▢▢▢▢       │ │
   │ └──────────────────┘ └─────────────────┘ │
   └──────────────────────────────────────────┘
   ```
3. **창 안 넘기기**: 내용이 길면 창 안을 손가락으로 위아래로 넘김 (창 높이는 화면 안에 들어가게 제한)
4. **설명(툴팁)**: 같은 배율로 크게, 탭한 곳 근처에서 화면 밖으로 안 나가게. 다른 곳을 탭하면 닫힘 (1차 그대로)
5. **대화창**: 아래쪽 가운데에 크게, 선택지 버튼도 크게 (대화 중 화면 탭 = 다음은 1차 그대로)
6. **화면 위 글자들**: 하단 HP · MP 막대, 오른쪽 위 퀘스트 안내, 버프 칸, 왼쪽 위 맵 이름, 골드, 아래 알림 글자도 1.3~1.5배로 (게임 화면을 너무 가리지 않는 선에서)
7. **확인 창** ("정말 팔까요?" 등) · 쓰러졌을 때 · 튜토리얼 안내 상자도 크게

## ④ 휴대폰 성능
- 휴대폰에서 처음 실행하면 스킬 이펙트 기본값을 **"보통"** 으로 (이미 직접 바꾼 사람은 그 설정 그대로)
- 메뉴(터치 버튼 설정 창)에 **"배터리 절약 (30프레임)"** 켬/끔 추가. 켜면 화면을 1초에 30번만 그려서 휴대폰이 덜 뜨겁고 배터리가 오래 간다 (게임 속도는 그대로)
- 확인: 이펙트가 가장 많은 녹스전 · 보스전을 테스트 모드로 띄워 끊김 측정 (이 환경은 PC 라서 실제 휴대폰보다 빠르다. 실제 기기 점검표에 "보스전 끊김" 항목을 넣는다)

## ③ 새 버전 안내
- 새로 배포하면, 휴대폰이 다음에 열 때 몰래 새 파일을 받아 두고 화면 아래에 **"새 버전이 준비됐어요 [지금 바꾸기]"** 안내
  - [지금 바꾸기] = 저장한 뒤 새로고침 / 그냥 두면 다음 실행 때 자동으로 새 버전
  - 전투 중에 갑자기 바뀌지 않게, 직접 누를 때만 바로 바뀐다
- 배포할 때마다 배포 번호(날짜 · 시각)가 붙어서 휴대폰이 새 버전을 알아본다. 화면 버전 표시는 `v2.1.0 모바일` 그대로

## ④ 배포 만들기 · 올리기
1. **배포판 만드는 스크립트** `tools/build_web.sh` (새 파일)
   - 복사: `index.html` · `css/` · `src/`(dev.js 빼고) · `icons/` · `manifest.webmanifest` · `sw.js` · 글꼴 라이선스(`css/fonts/jua/OFL.txt`)
   - `index.html` 의 테스트 모드 불러오는 줄을 뺀다 (배포판에는 파일도 없음)
   - 서비스 워커에 파일 목록 · 배포 번호를 써 넣는다
   - **코드 압축 (⑤-2)**: 배포판의 `src/**/*.js` 를 압축 도구(terser)로 줄인다
   - `.nojekyll`, 짧은 `README.md` (게임 소개 · 조작 · 세이브 안내 · 저작권 안내, 다른 게임 이름 없음), **`LICENSE` (⑤-3)**
2. **새 저장소 만들기**: 이 세션에서 만들 수 있으면 바로 만든다. 안 되면 사용자가 GitHub 웹에서 1분:
   github.com/new → 이름 `rpg-adventure` → **Public** → 나머지 그대로(README 체크 안 함) → Create repository
3. **올리기**: 배포판을 새 저장소 `main` 에 커밋 · 푸시 (커밋 내용 = 배포판만, 이 저장소의 기록은 따라가지 않음)
4. **GitHub Pages 켜기** (사용자가 한 번): 새 저장소 Settings → Pages → Source "Deploy from a branch" → Branch `main` / `(root)` → Save. 1~2분 뒤 주소가 열림
5. **다음부터 배포**: 개발 브랜치에서 고친 뒤 "배포해 줘" → 스크립트 → 새 저장소에 푸시 → 1~2분 뒤 반영 → 휴대폰에 "새 버전" 안내
- 주의: 공개 저장소라 게임 파일을 누구나 볼 수 있다 (무료 GitHub Pages 조건). 그래서 ⑤ 를 함께 한다. 배포 전에 배포판에 개인 정보 · 비밀 값(이메일 · 토큰 · 다른 프로그램 파일)이 없는지 검사 (스크립트가 자동으로 찾아서 있으면 멈춤)

## ③ 장비 비교 (인벤토리 설명)
- 인벤토리 장비를 탭하면 나오는 설명 아래에 **착용 중인 같은 부위 장비와 비교**:
  ```
  ── 착용 중 [강철 검 +3] 과 비교 ──
  예상 피해   +8.2% ▲     최대 HP  −20 ▼     방어  +3 ▲
  (세트 효과가 바뀌면: 바람 세트 2개 → 1개)
  ```
  - 실제로 바꿔 끼웠다고 치고 능력치를 다시 계산해서 비교 (세트 · 잠재 옵션 · 단련 효과 · 주문서 강화까지 그대로 반영)
  - 반지처럼 같은 부위가 둘이면 더 약한 쪽과 비교. 비어 있는 부위면 "빈 칸에 끼면"
  - 착용할 수 없는 장비(직업 · 레벨)는 "착용 불가: Lv.40 필요"만
- "예상 피해" 계산: 공격력 범위 × 치명타(확률 × 치명 피해) × 피해 % (사냥 기준. 보스 피해 %는 따로 한 줄)

## ④ 최고 장비 (표시 + 버튼)
- 인벤토리 장비 칸에서 **지금보다 좋은 장비에 ▲ 표시** (초록 화살표)
- 인벤토리 위에 **"⭐ 최고 장비 입기"** 버튼 → 바뀌는 목록을 확인 창으로 보여 주고 [입기]
  - 부위마다 "예상 피해"가 가장 높아지는 장비를 고른다. 같으면 최대 HP · 방어가 높은 쪽. 세트 효과를 위해 한 부위씩 바꿔 보며 더 좋아지지 않을 때까지 반복
  - 착용할 수 없는 장비는 건너뜀. 벗은 장비는 인벤토리로 (칸이 모자라면 그 부위는 건너뛰고 알려 줌)

  - 물약은 지금 있는 **자동 물약** 설정을 그대로 씀
- **하지 않는 일**: 포탈 타기 · NPC 대화 · 퀘스트 받기/완료 · 상자 열기 · 맵 이동 (↑ 키를 누르지 않는다. 위층 점프는 점프만)

## ① 자동 버튼 아이콘 A

- 보스 방에서 아직 못 쓸 때: 흐리게 + 남은 횟수 작은 숫자 (예: "3")

## ② 스킬 칸 안에서 가장 효율적인 스킬 고르기
지금: 1번 칸부터 차례로 쓸 수 있는 첫 스킬. 바꾼 뒤: 쓸 수 있는 스킬마다 점수를 매겨 가장 높은 것.
- **예상 피해 점수** = 스킬 배율(현재 스킬 레벨) × 타수 × **지금 맞힐 수 있는 몬스터 수** (스킬 모양대로 셈)
  - 근접 · 범위(`melee` · `aoe`): 스킬 폭 · 높이 안, 최대 대상 수까지
  - 투사체(`proj`): 바라보는 쪽 사거리 안, 관통 · 발사 수까지 / 낙하(`rain`): 앞쪽 범위 안 / 돌진(`dash`): 돌진 거리 안 / 후퇴 사격(`back`): 사거리 안
  - 기본 공격(100%, 1마리)보다 점수가 낮으면 기본 공격
- **재사용 시간이 긴 강한 스킬**(재사용 20초 이상, 4차 궁극기 등): 몬스터가 3마리 이상 맞을 때만 (한 마리에게 낭비하지 않게). 보스 방에서는 보스에게 바로
- **MP 가 30% 아래**면 MP 를 적게 쓰는 스킬 · 기본 공격 위주 (MP 1당 점수로 비교)
- **버프**: 꺼져 있으면 다시 (지금처럼). **회복**: HP 60% 아래일 때만
- 같은 점수면 칸 번호가 앞인 것 (사용자가 정한 순서 존중)
