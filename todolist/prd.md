# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.2 |
| 작성일 | 2026-11-02 |
| 상태 | 구현 완료 (M1~M5), 13장 구현 메모 참고 |

---

## 1. 개요

### 1.1 배경
하루 동안 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 진행 상황을 한눈에 확인할 수 있는 가벼운 웹페이지가 필요하다. 별도 설치나 로그인 없이 브라우저만으로 사용할 수 있어야 한다.

### 1.2 목표
- "오늘" 하루에 집중한 단순한 할일 관리 경험 제공
- 3초 안에 할일을 추가할 수 있는 빠른 입력 흐름
- 새로고침·브라우저 재시작 후에도 데이터 유지
- 데스크톱과 모바일 모두에서 쾌적하게 사용

### 1.3 비목표 (이번 범위에서 제외)
- 회원가입/로그인, 서버 동기화, 여러 기기 간 공유
- 프로젝트·태그 등 복잡한 분류 체계
- 반복 일정, 알림(푸시), 캘린더 연동
- 협업(할일 공유, 담당자 지정)

---

## 2. 대상 사용자 및 시나리오

### 2.1 대상 사용자
- 하루 업무/개인 일정을 간단히 정리하고 싶은 개인 사용자

### 2.2 핵심 사용자 시나리오
1. 아침에 페이지를 열어 오늘 할 일 5~10개를 연속으로 입력한다.
2. 일을 마칠 때마다 체크박스를 눌러 완료 처리한다.
3. 상단 진행률을 보며 남은 일을 확인한다.
4. 잘못 입력한 항목을 수정하거나 삭제한다.
5. 하루를 마무리하며 완료된 항목을 한 번에 정리한다.
6. 다음 날 페이지를 열면 어제 끝내지 못한 일을 오늘로 가져올지 선택한다.

## 3. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = 있으면 좋음, **P2** = 추후 고려

### 3.1 할일 관리 (P0)
| ID | 기능 | 설명 |
|---|---|---|
| F-01 | 할일 추가 | 입력창에 텍스트 입력 후 Enter 또는 "추가" 버튼. 빈 문자열/공백만 있는 입력은 무시. 최대 200자. 추가 후 입력창은 비워지고 포커스 유지 |
| F-02 | 완료 토글 | 체크박스 클릭으로 완료/미완료 전환. 완료 항목은 취소선 + 흐린 색 |
| F-03 | 할일 수정 | 텍스트 더블클릭(모바일: 수정 버튼) 시 인라인 편집. Enter 저장, Esc 취소. 빈 값으로 저장하면 수정 취소 |
| F-04 | 할일 삭제 | 항목별 삭제 버튼. 삭제 직후 5초간 "실행 취소" 토스트 제공 (P1) |
| F-05 | 데이터 유지 | 모든 변경 사항은 즉시 브라우저 localStorage에 저장 |

### 3.2 보기 및 정리 (P0~P1)
| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| F-06 | 오늘 날짜 표시 | P0 | 상단에 "2026년 11월 2일 (월)" 형식으로 표시 |
| F-07 | 진행률 표시 | P0 | "3 / 7 완료" 텍스트 + 프로그레스 바 |
| F-08 | 필터 | P1 | 전체 / 진행 중 / 완료 탭 |
| F-09 | 완료 항목 일괄 삭제 | P1 | "완료 항목 지우기" 버튼 (확인 다이얼로그) |
| F-10 | 순서 변경 | P2 | 드래그 앤 드롭으로 순서 변경 |
| F-11 | 우선순위 표시 | P2 | 항목에 "중요" 표시(별) 토글, 중요 항목 상단 정렬 |

### 3.3 날짜 전환 처리 (P1)
| ID | 기능 | 설명 |
|---|---|---|
| F-12 | 날짜 변경 감지 | 앱 로드 시 마지막 사용 날짜와 오늘 날짜 비교 |
| F-13 | 미완료 이월 | 날짜가 바뀌었고 미완료 항목이 있으면 해당 항목을 오늘 목록에서 빼서 "보류" 영역(`pending`)으로 옮기고, "어제 못 끝낸 N개를 오늘로 가져올까요?" 배너 표시 → [가져오기] / [버리기] |
| F-13a | 배너 무시 시 동작 | 사용자가 선택하지 않으면 **배너를 계속 표시하고 항목은 보류 상태로 유지**한다. 새로고침·재방문해도 선택 전까지 배너가 남는다. 보류 중에도 오늘 할일은 정상적으로 추가/관리할 수 있다 |
| F-13b | 보류 누적 | 선택하지 않은 채 날짜가 또 바뀌면, 그 날의 미완료 항목도 기존 보류 항목에 합친다. 배너 문구는 "이전에 못 끝낸 N개"로 바뀐다. 보류 항목은 원래 날짜(`sourceDate`)를 유지한다 |
| F-13c | 개별 선택 (P2) | 배너의 "골라서 가져오기"로 보류 항목을 하나씩 선택해 가져온다 |
| F-14 | 완료 항목 보관 | 날짜 변경 시 이전 날의 완료 항목은 오늘 목록에서 빼서 날짜별 기록(`history`)으로 옮긴다 |
| F-15 | 기록 보관 기간 | 기록은 **최근 7일**만 보관한다. 앱 로드 시 7일이 지난 날짜의 기록은 자동 삭제한다 |
| F-16 | 지난 기록 보기 | 하단 "지난 기록" 버튼으로 기록 화면을 연다. 날짜별(최신순)로 완료 항목과 완료 개수를 보여준다. 읽기 전용이며, 항목별 "오늘 다시 하기"로 오늘 목록에 복사할 수 있다 (P2) |

### 3.4 빈 상태 / 예외 상황
- 할일이 없을 때: "오늘 할 일을 추가해보세요" 안내 문구 + 입력창 강조
- 모두 완료했을 때: "오늘 할 일을 모두 끝냈어요 🎉" 메시지
- localStorage 사용 불가(시크릿 모드 등): 상단에 "이 브라우저에서는 저장되지 않습니다" 경고, 메모리 상에서만 동작

## 6. 데이터 설계

### 6.1 Todo 모델
```ts
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~200자, 앞뒤 공백 제거
  done: boolean;
  important: boolean;  // P2, 기본 false
  createdAt: string;   // ISO 8601
  completedAt: string | null;
  order: number;       // 정렬 순서 (P2 드래그용)
  sourceDate: string;  // "YYYY-MM-DD", 이 할일이 처음 만들어진 날짜 (이월돼도 유지)
  carriedFrom: string | null; // 보류로 옮겨질 때 속해 있던 날짜. 배너 문구("어제"/"이전에") 판단용
}

// 이월 대기 중인 미완료 항목
type Pending = Todo[];

// 날짜별 완료 기록 (최근 7일)
type History = Record<string /* "YYYY-MM-DD" */, Todo[]>;
```

### 6.2 저장 구조 (localStorage)
| Key | 값 | 설명 |
|---|---|---|
| `todayTodo.v1.todos` | `Todo[]` (JSON) | 현재 할일 목록 |
| `todayTodo.v1.lastDate` | `"YYYY-MM-DD"` | 마지막 사용 날짜 (로컬 시간 기준) |
| `todayTodo.v1.pending` | `Todo[]` (JSON) | 이월 선택을 기다리는 미완료 항목. 비어 있으면 배너 숨김 |
| `todayTodo.v1.history` | `History` (JSON) | 날짜별 완료 기록, 최근 7일 |
| `todayTodo.v1.filter` | `"all" \| "active" \| "done"` | 마지막 선택 필터 (P1) |

- 키에 버전(`v1`)을 포함해 향후 스키마 변경 시 마이그레이션 가능하도록 한다.
- 읽기/쓰기는 모두 try/catch로 감싸고, 파싱 실패 시 빈 목록으로 시작하며 손상된 원본은 `todayTodo.v1.todos.backup`에 보관한다.

### 6.3 상태 흐름
```
[앱 로드]
   → localStorage 읽기
   → lastDate != 오늘 ?
        ├─ 예: 완료 항목 → history[lastDate]로 이동
        │      미완료 항목 → pending에 합침
        │      todos = [] (오늘 목록 비움)
        └─ 아니오: 변경 없음
   → history에서 7일 지난 날짜 삭제
   → pending이 비어 있지 않으면 이월 배너 표시
   → lastDate = 오늘 저장 → 렌더링

[이월 배너]
   ├─ 가져오기: pending → todos 뒤에 추가 (sourceDate 유지), pending = []
   ├─ 버리기:   pending = [] (확인 다이얼로그)
   └─ 무시:     아무 변화 없음, 다음 로드에도 배너 유지

[사용자 액션] → state 변경 → localStorage 저장 → 화면 재렌더링
```

## 7. 기술 설계

### 7.1 기술 스택 (권장안)
| 항목 | 선택 | 이유 |
|---|---|---|
| 구조 | 순수 HTML + CSS + Vanilla JavaScript (ES Modules) | 기능 규모가 작아 프레임워크 불필요, 빌드 없이 바로 실행 |
| 저장소 | localStorage | 서버 없이 영속성 확보 |
| 스타일 | CSS 변수 기반 테마 토큰 | 라이트/다크 모드 전환 용이 |
| 배포 | 정적 파일 호스팅 (GitHub Pages 등) 또는 로컬 정적 서버 | 별도 백엔드 불필요. ES Modules는 `file://`로 열면 브라우저가 막으므로 정적 서버로 연다 |

> 기능이 P2 이상으로 커지면 React/Vue + Vite로 전환을 검토한다.

### 7.2 예상 파일 구조
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업 골격
├── css/
│   └── style.css     # 테마 토큰, 레이아웃, 컴포넌트 스타일
└── js/
    ├── main.js       # 진입점: 초기화, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── todo.js       # 할일 CRUD 순수 함수
    ├── date.js       # 날짜 포맷, 날짜 변경 판단
    ├── rollover.js   # 날짜 변경 처리: 이월(pending), 기록(history) 정리
    └── render.js     # DOM 렌더링 (기록 화면 포함)
```

### 7.3 모듈 책임
| 모듈 | 책임 | 주요 함수 (예시) |
|---|---|---|
| `todo.js` | 상태를 받아 새 상태를 반환하는 순수 함수 | `addTodo`, `toggleTodo`, `editTodo`, `removeTodo`, `clearDone` |
| `store.js` | 상태 보관, 구독, 영속화 | `getState`, `dispatch`, `subscribe`, `load`, `save` |
| `date.js` | 로컬 날짜 처리 | `todayKey()`, `formatKoreanDate()`, `isNewDay(lastDate)`, `daysBetween(a, b)` |
| `rollover.js` | 날짜 변경 시 상태 정리 (순수 함수) | `rollover(state, today)`, `acceptPending`, `discardPending`, `pruneHistory(history, today, 7)` |
| `render.js` | 상태 → DOM | `renderHeader`, `renderList`, `renderFooter` |
| `main.js` | 초기화 및 이벤트 위임 | `init()` |

- 리스트 이벤트는 `<ul>`에 이벤트 위임 방식으로 처리한다.
- 날짜는 UTC가 아닌 **사용자 로컬 시간** 기준으로 판단한다.

## 13. 구현 메모 (2026-11-02)

### 실행 방법
```
python -m http.server 5173 --directory todolist
```
브라우저에서 http://localhost:5173 을 연다. (`index.html`을 더블클릭해서 열면 ES Modules가 차단되어 동작하지 않는다.)

### 설계에서 추가·구체화된 부분
- `Todo.carriedFrom` 필드 추가: `sourceDate`는 원래 날짜로 유지하고, 배너 문구는 보류로 옮겨진 날짜 기준으로 판단한다.
- 이전 날짜에서 가져온 항목에는 "11/1부터" 배지를 표시한다.
- 페이지를 열어둔 채 자정이 지나도 1분 주기 확인과 탭 복귀(`visibilitychange`) 때 날짜 변경을 처리한다.
- 다른 탭에서 바꾼 내용은 `storage` 이벤트로 반영한다.
- 키보드로 항목을 삭제하면 이웃 항목으로 포커스가 이동한다.
- 드래그 정렬은 마우스 환경에서만 핸들(⠿)을 노출한다. 터치 환경과 키보드로는 순서를 바꿀 수 없다.

- 10장 체크리스트 전 항목 통과: 빈 입력 무시, 200자 제한, 새로고침 후 유지, Esc 취소, HTML 문자열 그대로 표시, 진행률 갱신, 이월 배너 표시·유지·누적, 기록 이동, 8일 이상 지난 기록 삭제, localStorage 차단 시 동작, 다크 모드, 360px대 폭(375px)에서 가로 스크롤 없음
