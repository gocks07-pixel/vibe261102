# PRD: QA 프로필 웹사이트 (DemoPort)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | DemoPort |
| 목적 | QA 엔지니어 개인 프로필 및 검증 포트폴리오 웹사이트 |
| 연락처 | hclee@infiniq.co.kr |
| 주 검증 및 평가 분야 | 전장사업검증 (SBCM, 램프 제어기) |
| 작성일 | 2026-11-03 |

## 2. 배경 및 목표

전장(자동차 전기·전자) 분야 검증 경력과 역량을 한눈에 보여줄 수 있는 프로필 웹사이트를 만든다.

- 방문자(채용 담당자, 협력사, 고객사)가 QA 엔지니어의 전문 분야를 빠르게 파악할 수 있도록 한다.
- SBCM, 램프 제어기 검증 경험과 수행 프로젝트를 구조적으로 정리한다.
- 이메일을 통한 연락 경로를 명확히 제공한다.

## 3. 대상 사용자

| 사용자 | 기대하는 것 |
|---|---|
| 채용 담당자 / 헤드헌터 | 경력 요약, 전문 분야, 연락처 |
| 고객사 / 협력사 담당자 | 검증 수행 이력, 검증 방법론, 사용 툴 |
| 동료 엔지니어 | 기술 스택, 검증 사례 |

## 4. 핵심 콘텐츠 (사이트 구성)

### 4.1 Hero (메인)
- 이름 / 직무 타이틀 (예: "Automotive Electronics QA Engineer")
- 한 줄 소개: 전장사업검증 전문 — SBCM, 램프 제어기
- CTA 버튼: "연락하기" (mailto:hclee@infiniq.co.kr), "프로젝트 보기"

### 4.2 About (소개)
- 경력 요약 및 QA 철학
- 주요 역량 키워드

### 4.3 전문 분야 (Expertise)
- **SBCM (Smart Body Control Module)**
  - 바디 전장 기능 검증 (도어, 윈도우, 와이퍼, 실내등 등)
  - CAN/LIN 통신 검증, 진단(UDS) 검증
- **램프 제어기 (Lamp Control Unit)**
  - 헤드램프 / 리어램프 / 방향지시등 제어 로직 검증
  - 고장 감지(Fault Detection) 및 Fail-safe 동작 검증
- 공통 검증 영역
  - 요구사항 기반 테스트 설계, 기능/회귀/경계값 테스트
  - HILS 기반 검증, 결함 관리 및 리포팅

### 4.4 검증 프로세스 (Process)
- 요구사항 분석 → 테스트 계획 → 테스트 케이스 설계 → 수행 → 결함 리포트 → 회귀 검증
- 다이어그램 또는 단계별 카드 형태로 시각화

### 4.5 프로젝트 / 포트폴리오 (Projects)
- 프로젝트 카드: 프로젝트명, 기간, 대상 제어기, 역할, 수행 내용, 성과
- 고객사 기밀 사항은 일반화된 표현으로 기재

### 4.6 기술 스택 / 툴 (Skills & Tools)
- 예: CANoe, CANalyzer, Trace32, HILS, JIRA, Excel/VBA, Python 등 (실제 사용 툴로 확정 필요)

### 4.7 Contact (연락처)
- 이메일: hclee@infiniq.co.kr (mailto 링크)
- 선택: 이메일 주소 복사 버튼

## 6. 비기능 요구사항

- **성능**: 초기 로딩 2초 이내, 정적 사이트로 구성
- **접근성**: 시맨틱 HTML, 충분한 색 대비, 키보드 탐색 가능
- **유지보수**: 콘텐츠(프로필, 프로젝트)를 코드와 분리된 데이터로 관리
- **보안/기밀**: 고객사명·차종·내부 문서 등 기밀 정보 비노출

## 7. 디자인 가이드

- 톤: 신뢰감 있는 전문가 이미지, 깔끔하고 기술적인 느낌
